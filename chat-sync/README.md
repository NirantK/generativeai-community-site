# Cloudflare-hosted WhatsApp archive sync

The live preflight and authenticated two-group sync passed on 2026-09-24. Scheduling is enabled. The archive is limited to available synced text; it is not a complete copy of WhatsApp history.

## Architecture

- A native Workflow schedule synchronizes every 15 minutes. The Worker has no Cron Trigger or public route. A leased Durable Object skips overlapping runs without starting a second WhatsApp session. Failures retry on the next slot, while last-success advances only after verification.
- One leased Durable Object owns the WhatsApp session and starts a native Linux `wacli` 0.18.2 container. No public Worker route, workers.dev URL, or HTTP administrative endpoint is enabled.
- Private R2 bucket `genaicommunity-chat-sync-private` stores the session credential, sanitized authorized-group cache, pending sanitized export, and non-content sync results. Never enable public access. Treat the session snapshot as a credential.
- Cloudflare R2 lifecycle rule `chat-sync-checkpoints-30-days` expires immutable exports under `session/checkpoints/` after 30 days. Cloudflare processes expirations automatically, typically within 24 hours of expiry. The active `session/latest.tar.gz` is outside this prefix and must remain available for session restore. The default multipart-abort rule remains enabled.
- The container syncs only `120363049558306142@g.us` (The GenerativeAI Group) and `120363323644237261@g.us` (Job Posts & Talent). The first group's legacy cutover is preserved; the second group uses available wacli history. It retains namespaced IDs and applies explicit deletions; absence never deletes history.
- The Worker writes through the D1 binding. Scheduled runs do not use Wrangler OAuth, a Mac, or an account API token. GitHub needs a deployment token only at deployment time.
- Each per-message database batch updates its search entry atomically. Administrator hiding and group publication state survive. Last-success advances only after search-index verification. Pending exports survive import failure.
- The container checkpoint drops unrelated cached chats, contacts, locations, and media, and redacts phone-shaped text before R2 upload. `session.db` is a private authentication credential, not published chat data. Job Posts & Talent was published after its cloud import and search-index verification on 2026-09-24.

## Operations

1. Inspect `genaicommunity-chat-sync` Workflow instances and the private R2 `last-success.json` after a run. The published group rows in D1 must have visible messages and a consistent `chat_search` index.
2. After a container image deployment, run authenticated preflight with `{"preflight":true}` before a controlled `{"force":true}` sync. Preflight stops the reserved container so the next run uses the updated image.
3. If the cloud session needs replacement, stop local wacli sync processes, create a private checkpoint with `chat-sync/container/checkpoint.py:checkpoint(Path('/Users/nirantk/.wacli-codex'))`, and upload it to `session/latest.tar.gz`. Never run the same session on the Mac and Cloudflare concurrently.
4. Keep runtime credentials out of the image, logs, and repository. Delete temporary local checkpoints after verification.
5. Verify retention with `CLOUDFLARE_ACCOUNT_ID=076c525b59739562570401e48fc0651c npx wrangler r2 bucket lifecycle list genaicommunity-chat-sync-private --config chat-sync/wrangler.jsonc`. The `chat-sync-checkpoints-30-days` rule must be enabled with prefix `session/checkpoints/` and expiry of 30 days. Do not apply a bucket-wide expiry: it would remove the active session and sync state.

If a terminated Workflow leaves its one-hour lease behind, first verify that exact instance is **terminated**, no other sync instance is running, and `session/recovery-required` is absent. An account operator can then trigger the private Workflow with `{"terminatedLeaseOwner":"EXACT_TERMINATED_INSTANCE_ID"}`. Recovery succeeds only when that owner still holds a lease acquired at least 10 minutes ago and the container is stopped. It does not start wacli, alter the session checkpoint, or import messages. Never use it on an active instance.

The Job Posts & Talent cloud cache began on 2026-09-16 and initially held only 20 records. Coverage `publicationCounts` distinguishes text candidates from media, reactions, empty text and deletions. To request one older-history batch from the phone for that group alone, trigger the private Workflow with `{"force":true,"backfillJobs":true}`. This asks wacli for at most 500 older messages, then exports the authorized groups from its cache and performs verified import; it does not start a separate live sync. The operator can repeat verified batches while the oldest cached timestamp moves earlier, stopping when WhatsApp returns no older history or the source fails. A backfill is best-effort: the phone must answer, and a successful request does not prove complete history. If the request fails, keep the previous archive and retry only after checking the Workflow error and session checkpoint. Regular scheduled runs never request history backfill.

If a history request completed but the following live sync failed, and `session/recovery-required` is absent, an operator can trigger `{"force":true,"cachedOnly":true}`. It restores the last saved private checkpoint, exports only the authorized groups from that cache, then uses the normal sanitizer, D1 import and verification. It makes no WhatsApp network sync or history request. Check coverage against the previous checkpoint: cache-only success does not prove that the phone returned older history.

On 2026-09-24, five checkpoint copies were found to contain unrelated cached chat rows and deleted after explicit owner approval. Five audited copies containing only the two intended groups were kept, along with `session/latest.tar.gz`. The retention rule expires immutable copies after 30 days. New checkpoints close SQLite before archiving and pass a WAL-mode privacy test.

A failed/empty/capped source export causes per-group `could-not-sync`, retains its checkpoint and published rows, and permits healthy groups to import. A live sync or session failure prevents the whole import. Checkpoint restoration failure requires operator action. If WhatsApp revokes the session, it still requires pairing again; hosting does not remove WhatsApp authentication requirements.

## Three-group routing and review

The authorized archive additionally includes Project Demos & Events (`120363297860953641@g.us`); verify its exact live WhatsApp name before backfill. `{"force":true,"backfillDemos":true}` requests a bounded older-history batch only for that group. Repeat while coverage grows, stopping on exhausted/no-progress history. Never infer deletion from missing cache data. New group publication follows count, privacy and search verification.

Migration 0009 adds the routing review and send ledger. Full original incoming top-level text and quote sender travel only from the live container response to Workers AI inside the same Durable Object method; they are removed before R2 writes, Workflow step returns and checkpoints. No AI Gateway payload logging is enabled. Phone-redacted D1 history seeds the review pool when original text is unavailable. Model errors do not prevent archive import; they cause no public reply.

Use `{"modelEvaluation":true}` to exercise Clef on the deployed Cloudflare AI binding, including ambiguous content and prompt injection. `{"seedRouting":300}` seeds a historical review batch; ordinary syncs replenish 18 examples. Labels on `/admin` reveal predictions only after the admin's choice, keep a held-out fraction, and build a versioned evaluation/example bank. Hosted Clef weights are not automatically trained.

All routing controls require an administrator browser session and CSRF protection. Automatic replies start disabled. The server enforces seven trial days, 30 reviewed high-confidence proposed moves and 95% precision. After that, `/admin` can request one controlled test on the next fresh qualifying post in explicitly selected source/destination groups. Only after WhatsApp acceptance does the server allow enabling automatic replies. They quote the original message and include `- Sent by my agent`. Replies are limited to original posts no older than 12 hours, checked during classification and again at the send boundary. Editing an old message does not reset this clock. Historical backfills never receive replies; older reviewed examples remain useful for evaluation. Sender metadata exists only during a live run, so stale/history suggestions cannot be sent later. Edits never cause a second reply to the same message. `sending` or `uncertain` ledger entries require inspection and recorded reconciliation, not blind retries. Pause is immediate for future claims.

Reviewed examples are frozen in policy versions. `/admin` can request a candidate-policy evaluation on at least 12 held-out labels covering all three groups, with at least six training examples. Activation requires at least 90% held-out accuracy, at least 95% proposed-move precision, no inference errors and no accuracy regression versus the active policy. Activating a candidate pauses replies and requires another controlled test. Labels do not silently change the active prompt.

If the cloud demos cache is empty, wacli 0.18.2 cannot request history without an anchor. An operator may supply `demosAnchor:{messageId,timestamp,fromMe}` with forced demos backfill, using authentic metadata from an existing same-group cache. The exporter verifies the live group identity first, inserts only metadata into an empty cache and requests history in Cloudflare. Never supply sender, message text, fabricated metadata or a replacement session. An empty-text anchor is not a published message or evidence of complete coverage.

An authentic pre-cloud demos cache can be transferred as a **sanitized** private `bootstrap/demos-cache.json` artifact and imported with `{"force":true,"bootstrapDemos":true}`. It contains only exact-source message IDs, timestamps, from-me flags, redacted text and redacted display names, plus the known metadata-anchor ID. The cloud exporter verifies the live group identity and sanitizes again, inserts missing records without overriding cloud edits/deletions, and imports through the normal search-verification path. Delete the artifact only after verified success. This is a one-time cache transfer, not a local sync. A group with no publishable text retains its failed checkpoint while healthy groups import.

The admin review set defaults to Trial proposed moves, which contains only actual assessed high-confidence proposals and excludes already labeled posts. The learning set retains the active-learning quotas. Operator Workflow payload `{"seedProposals":300}` searches unassessed historical archive posts with hiring/showcase/event cues, then lets Clef assess them with unchanged thresholds. Cues never assign labels or manufacture proposals; historical sampling never sends replies.
